本期为什么改？

先理解「痛点 → 本期方案」，后面的状态和按钮才有意义。

过去的问题

  • 填资太重、太靠前 → 有价值用户筛得晚，销售介入晚
  • 海外链路不完整 → 海外资料销售看不到 / 跟不下来
  • 人审临近拒绝缺少规范退回 → 补件断流
  • 材料说明不清 → 一次交件率低、反复驳回
  • 销售不知道用户到哪一步 → 跟单时机乱

本期怎么解

  • 分阶段填资：先预审戳额筛客，再终审详资
  • 本土 / 海外分流：同一套阶段，字段按流程属性区分
  • 用户状态：销售按状态决定何时跟、能改什么
  • 退回 / Pending：人审与销售协同补件，用户路径不同
  • Sample + 多图/PDF：提升一次交件率
【贴图占位】培训开场对比图 建议：左「旧流程：一次填完全部再戳额」流程图；右「新流程：预审轻量 → 有额 → 终审详资」流程图。

谁在这条链路上？

用户 APP

借款人 / Co-maker

  • 选本土 / 海外
  • 完成预审 / 终审提交（戳额）
  • 发标页选担保人、确认借款
  • 人审退回：在退回页补件并重新提交终审
  • Pending：无感知，仍显示审核中
销售 / 销管

销售代填后台

  • 看用户状态，决定跟进时机
  • 协助填本人资料 / 维护已有担保人
  • 只能保存，不能代提交戳额
  • 退回：改资料后催用户 APP 提交
  • Pending：改标红项 → 保存并通知审核员
人审

人审后台

  • 按借款人 → 联系人 → 担保人审阅
  • Materials 须逐项 Pass
  • 结论：通过 / 退回 / Pending / 拒绝
  • 退回 / Pending 字段会下发给销售标红
  • Pending 等销售改完或 3 日到期再继续审
记住一句话：用户负责「提交戳额 / 确认借款」；销售负责「帮填与催办」；人审负责「审材料与下结论」。三角交互最常出在 退回 和 Pending。
角色菜单：销售代填 · 销售代填管理 · 人审普通 / 管理员

预审 · 终审 · 发标：分别填什么？

预审戳额节点

轻量筛客

  • 活体
  • 身份信息（护照等）
  • 基础信息
  • 中介信息（本土含 Agency Proof 等）

提交后触发预审戳额 → 初审额或拒绝。

终审戳额节点

详资拿终审额

  • 工作 / 雇主信息
  • 联系人 1 / 2
  • 可选预填 Co-maker（不完整不拦提交）

提交后触发终审戳额。销售可在终审提交前协助代填。

发标页

选担保人借出

  • 选择已有 / 新增担保人
  • 已注册担保人手机号不可改
  • 确认借款 → 等担保人 H5 确认

担保确认后进入机审 + 人审。

【贴图占位】三节点页面对照 左：预审填资截图；中：终审 Work/Contacts；右：发标页 Co-maker 选择（含 Edit）。
节点内可来回改页；只有点「提交戳额」才做整段完整性校验。

APP 侧：销售需要会向用户解释的变化

材料与上传

  • 强制 Sample：Visa / 收入证明 / 担保人住址证明 —— 点上传先看样例
  • 其它材料：字段旁 Sample 链接
  • 合同 / 收入 / 住址证明：最多 6 图 或 1 份 PDF（不能混传）
  • Co-maker 证件照：同一字段正面 + 反面

结论相关的 APP 表现

  • 退回：独立退回页，只改被退回项 → 提交后二次终审
  • Pending：用户仍看「审核中」，无补件页
  • 拒绝：发标拒绝页；人审可勾选本次不禁言
  • 「我的页面」编辑入口隐藏，避免乱重戳额

额度失效 / 材料失效（对客话术）

  • 额度失效：首页 Renew → 只重新终审（不做预审）
  • 材料失效：同退回补件页 → 只补失效材料 → 重新终审
【贴图占位】Sample 弹窗 / 退回页 / Renew 入口 各贴一张典型截图即可。

用户状态：销售怎么读进度？

后台统一叫「用户状态」。填资阶段看人维度；Co-maker 确认发标后看标的维度——但都落在同一套标签里。

阶段 关键销售标签 你该做什么
筛客前 注册未填资 · 初审中 · 初审拒绝 可协助预审资料；初审中勿催改；拒绝一般少跟
拿终审额 ★ 终审填资 · 终审中 · 终审拒绝 有初审额时重点催终审资料；提交后等结果
借出前 ★ 有额未借 · ★ 待担保确认 推确认借款；催 Co-maker；本人资料已锁
发标后 发标审核中 · 发标拒绝 · 放款中/成功/失败 审核中只读；拒绝结案告知；放款异常走救回
人审协同 ★ 人审退回 · ★ 人审 Pending 退回改完催用户 APP 提交；Pending 改完通知审核员

优先跟进的 5 个状态（带行动提示）

★ 终审填资

已有初审额，催补详资冲终审。

  • 本人资料：可代填（权限内）
  • 保存后：提醒用户 APP 提交终审

★ 有额未借

推确认借款 / 补担保与账户。

  • 本人资料：只读
  • 可维护未担保中的 Co-maker

★ 待担保确认

催 Co-maker 确认；必要时取消借款换人。

  • 本人资料：只读
  • 担保中的 Co-maker 不可改

★ 人审退回 / Pending

协同补件，响应要快。

  • 退回：标红优先，可改权限内全部本人资料 → 仅保存
  • Pending：只改标红 → 保存并通知审核员
【贴图占位】销售列表默认队列截图 标注：置顶的「人审退回 / Pending」、状态标签、编辑入口。

销售列表：默认看谁？怎么搜？

普通销售

默认队列

  • 仅本人名下（用户归属）
  • 状态：终审填资 / 人审退回 / Pending / 待担保确认
  • 退回、Pending 置顶高亮
  • 其余按注册时间近→远

未分配用户不在默认列表；用手机号 / User ID 搜出后点编辑 → 自动认领为当前销售。

筛选项 / 搜索项

  • 筛选项：流程属性、用户状态
  • 搜索项：User ID / 手机号
  • 用户归属：是否在销售名下
规则：
· 筛选项受用户归属控制 → 只能筛本人名下
· 搜索项不受归属控制，也不受筛选项限制 → 用 User ID / 手机号搜，无论流程/状态筛了什么，都能搜出
销管

默认队列

  • 默认只看全部人审退回 / Pending
  • 可按销售筛选、换绑跟进销售
  • 可改销管专属字段
搜索注意：额度失效后后台可能搜不到该用户；用户重新获额后才能再搜到，并以最新可监听状态展示。
【贴图占位】列表筛选条 + 搜索框 + 销管换绑

详情代填：能改什么？

场景本人资料保存后
终审提交前（如终审填资）权限内可编仅保存 · 催用户 APP 提交
人审退回可编（退回项标红必改）仅保存 · 用户 APP 重提终审
人审 Pending仅标红项保存并通知审核员（不重跑终审）
审核中 / 有额未借 / 待担保确认等本人只读—
铁律：BK 任何状态都不能代用户提交预审 / 终审戳额。

资料始终可见；没有值显示空白。字段范围与 APP 填资对齐。

销管专属 & 硬性禁止项

仅销管可改（普通销售永远不能改）

  • 姓名三分、护照号、性别、生日、母亲娘家姓
  • 护照照、PH 住址省市区、OFW Agency、邀请码 / 活动码
  • 联系人姓名 / 手机 / 关系
  • Co-maker 姓名、关系、证件类型/号、性别、生日、住址

细则以填资表 / PRD F08.3 为准，培训时以系统权限提示为准。

任何人都不能在后台做的事

  • 改用户注册手机号 / Co-maker 手机号
  • 后台新增担保人（只能维护用户已添加的）
  • 改担保中的 Co-maker
  • 改 Purpose of Loan（默认 Other，只读）
  • 代提交预审 / 终审戳额

可改提醒

  • Agency Proof：销售在可编窗口可改
  • Co-maker ID photo：正面 + 反面同一字段
【贴图占位】销管专属字段锁图标 / Purpose of Loan 只读

人审作业主流程

1
领单 / 被分配

列表有 Pending 列，标识挂起等销售改资料的单。

2
按模块审阅

借款人 → 联系人 → 担保人。证件图（Materials）必须逐项点过。

3
文本字段

默认视为通过；有问题再标退回 / Pending / 拒绝。

4
材料门禁

Materials 未全部打标 → 四按钮置灰，提示先完成材料审核。

5
提交结论

通过：底部直接提交。退回 / Pending / 拒绝：打开确认结论弹窗。

【贴图占位】人审详情整页 标注模块分区、Materials Pass、底部四按钮。

互斥规则（必记）

  • 有退回或拒绝标记时，不能点 Pending
  • 担保人手机号：可看，不能退回 / Pending / 拒绝
  • 通过：要求全部必审图片已 Pass，且无问题标

四种结论：标的怎么变？谁会收到？

结论 标的 APP 销售 人审下一步
通过 进入放款 后续放款/还款 只读 结束本案审阅
退回 失败 退回页补件 → 二次终审 字段标红；可代改仅保存；通知跟进销售/销管 等补件重提后再进入后续审核链路
Pending 不变（仍审核中） 无感知，仍审核中 只改标红；保存或 3 日到期回待审 释放后原审核员继续审
拒绝 失败 发标拒绝页 只读；可勾选禁言豁免 结案
【贴图占位】确认结论弹窗四态对照 通过可不弹窗；退回 / Pending / 拒绝弹窗字段清单示意。

交互② 人审退回 — 系统怎么走？

退回 = 标的失败 + 前台把退回字段同时下发给 APP 与销售。

1
人审 标退回字段 → 确认结论提交

走风控 / 资产 → 标的失败。

2
业务前台闭环

落库退回清单；清空旧值；用户状态 → 人审退回。

3
同时下发两路

APP 退回页只展示退回字段；销售 详情标红 + 通知跟进销售 / 销管。

4
补件完成后

用户 APP 提交 → 二次终审（不重走整段预审）。

【贴图占位】退回时序示意 / 三端对照 左人审打标；中销售标红详情；右 APP 退回页。可用箭头标「同时下发」。
退回场景允许重新跑额覆盖；以最后一次提交为准。用户生命周期可多次退回。

交互② 退回后：销售 / 用户怎么配合？

销售动作
  1. 打开退回任务（默认队列置顶）
  2. 优先改标红字段；权限内其它本人资料也可改
  3. 点保存（不是提交终审）
  4. 通知用户：请到 APP 退回页检查并提交
销售保存不会触发二次终审。
用户动作
  1. 首页进入退回补件
  2. 只改被退回项（销售已改的会回显）
  3. 提交 → 进入终审审核中
  4. 出新额度后再走发标
用户与销售可并行改；最终以提交时刻的正式资料为准。
【贴图占位】销售「仅保存」提示条 + APP 退回提交按钮 强调按钮文案差异，避免销售以为已重新提交。

交互③ Pending — 用户无感知

1
人审 只勾 Pending 字段（不能同时有退回/拒绝）

审核单挂起；标的不变；不经风控/资产失败。

2
APP

仍显示审核中，用户不能改、也没有补件页。

3
销售

只改标红 Pending 项 → 点「保存并通知审核员」。

4
释放

销售保存成功，或3 日到期自动释放 → 回人审待审，通知原审核员继续审。不重跑终审。

Pending 是「人审 ↔ 销售」闭环；对用户尽量少打扰。
【贴图占位】Pending 列表标识 + 销售仅可编标红项 + 倒计时/到期说明

交互④ 人审拒绝

链路

  • 人审打拒绝标 → 确认结论提交
  • 经风控 / 资产 → 标的失败
  • 用户看到发标拒绝页
  • 销售侧只读，结案告知

禁言豁免

人审可勾选「本次不禁言」。无论是否豁免，对外状态仍是发标拒绝。

【贴图占位】拒绝确认弹窗（含禁言豁免勾选）+ APP 拒绝页

额度失效 / 材料失效：怎么跟？

对用户（APP）

  • 额度失效：Renew → 重新发起终审（不做预审）
  • 材料失效：补件页只更新失效材料 → 重新终审

对销售（BK）

  • 失效本身可能不刷新后台状态（无监听消息时）
  • 额度失效后可能搜不到用户；重新获额后再搜
  • 若当时本就不可编，仍不能改；需用户先走 APP 入口推进
  • 依旧：只能保存，不能代提交

常见误操作 & 问答

容易做错

  • 退回后销售以为点保存就等于重新终审
  • Pending 时去催用户改 APP（用户改不了）
  • 普通销售改销管专属字段失败后反复点
  • 想在后台新增担保人 / 改已注册手机号
  • 人审有退回标还点 Pending
  • Materials 没点完就想提交结论

快问快答

  • Q：销售改完退回，用户 APP 能看到吗？
    A：能回显；但必须用户自己提交。
  • Q：Pending 会不会把标的打失败？
    A：不会。
  • Q：确认借款算发标吗？
    A：不算；Co-maker 确认后才发标。
  • Q：Purpose of Loan 为什么改不了？
    A：默认 Other，双端只读。

销售
  • 看状态再决定跟不跟
  • 默认跟：终审填资/退回/Pending/待担保
  • 只能保存，不代提交
  • 退回：改完催用户提交
  • Pending：改完通知审核员
人审
  • 材料逐项 Pass
  • 四结论：过/退/挂/拒
  • 退回与拒绝互斥 Pending
  • 退回下发 APP+销售
  • Pending 只找销售，3 日到期
